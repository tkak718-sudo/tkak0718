# 問い合わせフォーム 入力項目テンプレート

配布した100社のフォームを実際に取得して、どの項目が求められるかを数えた結果に基づく。
`profile.json` を用意するときの手引きとして使う。

## 用意しておく項目

出現率は100社を機械的に走査した**下限値**（`name`と`placeholder`だけで数えたもの）。
実際はラベル文言からも拾うので、これより高い。

| 優先 | 項目 | profile.jsonのキー | 出現率 | 記入例 | 注意 |
|---|---|---|---|---|---|
| 必ず要る | メールアドレス | `email` | **70%** | `crowdbasket@active-c.jp` | 返信が来る先。フリーメール不可のフォームがある |
| 必ず要る | 電話番号 | `tel` | **35%** | `03-0000-0000` | ハイフン有無を問うフォームがある。有りで統一 |
| 必ず要る | お問い合わせ内容 | `body` | **34%** | 本文（下記） | 最重要。ここだけは使い回さず作り込む |
| 必ず要る | お名前 | `name` | **32%** | `小熊 夢樹` | 姓名が別欄のフォームもある |
| 高頻度 | フリガナ | `name_kana` | **24%** | `オグマ ユメキ` | カタカナ指定が多い。ひらがな欄は稀 |
| 中頻度 | URL・ホームページ | `url` | 11% | `https://example.co.jp` | 自社サイト |
| 中頻度 | 部署・所属 | `dept` | 10% | `営業部` | |
| 中頻度 | 会社名・団体名 | `company` | 9% | `株式会社クラウドバスケット` | 法人格まで入れる |
| 中頻度 | 件名 | `subject` | 9% | 下記 | 選択式（プルダウン）のことも多い |
| 中頻度 | メール（確認用） | 自動 | 7% | — | `email` と同じ値が自動で入る |
| 低頻度 | 郵便番号 | `zip` | 6% | `100-0001` | |
| 低頻度 | 住所 | `address` | — | `東京都千代田区千代田1-1` | 都道府県が別プルダウンのことがある |

**メール70% / 電話35% / 本文34% / 氏名32% / フリガナ24%** の5つを埋めれば、ほとんどのフォームは通る。

## 件名の例

プルダウンの場合は「提案・営業・サービス・協業・その他」の順で自動選択される。
自由入力の場合はこれを使う。

```
LINEでチケット・グッズ販売ができるサービスのご案内
```

## 本文のテンプレート

`{会社名}` はCSVの会社名に置き換わる。

```
{会社名}
ご担当者さま

突然のご連絡を失礼いたします。株式会社クラウドバスケットの小熊と申します。
貴団体の公演情報を拝見し、ご案内が可能と考えご連絡いたしました。

LINE公式アカウント上でチケットと物販の販売、購入者へのセグメント配信までを
行えるサービスを提供しております。

・チケットのもぎりから来場者データの蓄積まで一気通貫
・既存のプレイガイド販売と併用可能
・紙台帳やExcelでの会員管理を置き換え

ご不要でしたら本メッセージは破棄いただき、以後のご連絡が不要な旨を
ご返信いただければ、以後ご連絡いたしません。

株式会社クラウドバスケット 小熊 夢樹
crowdbasket@active-c.jp
```

### 本文で外せない3点

1. **なぜその団体に送ったか** — 「貴団体の公演情報を拝見し」の部分。
   ここが無いと一斉送信と分かり、読まれずに終わる
2. **何ができるかを3点以内** — 長い説明はフォームの文字数制限に掛かる
3. **連絡停止の導線** — 相手が止められる手段を必ず書く。
   フォーム営業で苦情になるのは、断っても止まらないケース

### 業種別に差し替えるとよい箇所

配布リストは業種が分かれているので、2行目の切り出しだけ変えると通りが良くなる。

| 業種 | 差し替え文 |
|---|---|
| 文化事業・公演主催（財団） | 貴財団の自主事業公演を拝見し |
| 演劇鑑賞団体・音楽鑑賞団体 | 会員制で例会公演を運営されていると伺い |
| 独立リーグ野球・ラグビー | 主催試合のチケット販売について |
| アマチュアオーケストラ・吹奏楽団 | 定期演奏会のチケット取り扱いについて |
| 演芸・伝統芸能 | 定期公演のチケット販売について |

## 事前に知っておくべきフォーム側の事情

100社の実測。

| 事象 | 件数 | 対応 |
|---|---|---|
| `<form>` を検出 | 69 | 自動入力の対象 |
| **CAPTCHAあり** | **21** | **自動送信しない。手動対応リストへ** |
| 確認画面を挟む | 11 | 「確認する」→「送信する」の2段。ツールは分けて処理する |
| 到達不可 | 4 | URLが変わっている。手で確認 |
| 営業お断りの記載 | 0 | 配布前に4社を除外済み |

**CAPTCHAの21社は手動になります。** 結果CSVの理由欄に「CAPTCHAあり」と出るので、そこで振り分ける。

## 入力後の確認

`--headed` を付けて最初の数件をブラウザで見る。特に見るべきは以下。

- フリガナ欄に漢字が入っていないか（カタカナ指定のフォームで弾かれる）
- 本文が途中で切れていないか（文字数制限）
- 同意チェックが入っているか
- 「確認する」で止まらず、最後の「送信する」まで到達しているか
