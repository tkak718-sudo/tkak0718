# crowdbasket-CRM

営業リード管理のCRM。単一のHTMLファイルで動作し、データはFirestoreに保存されます。
ビルド手順はありません（外部ライブラリはCDNのFirebaseのみ）。

## 構成

```
crm-deploy/
  index.html      アプリ本体。これ1つで完結
wrangler.jsonc    配信設定。crm-deploy/ の中身が公開URLの直下になる
package.json      wrangler のバージョンを固定
```

## 更新のしかた

`main` ブランチが公開中の内容です。**`main` を更新すれば自動で公開されます。**

Cloudflare Workers の Workers Builds がこのリポジトリに繋がっており、`main` への
プッシュを検知して `npx wrangler deploy` を実行します。ファイルを手元にダウンロード
したりアップロードしたりする必要はありません。

1. `crm-deploy/index.html` を編集する
2. `main` にプッシュする
3. Cloudflare の「Deployments」タブに新しいバージョンが増えれば完了
4. 公開URLをスーパーリロード（Ctrl+Shift+R / Cmd+Shift+R）して反映を確認する

デプロイしても既存のクライアントデータはFirestore側にあるため消えません。

### 手元からデプロイする場合

自動デプロイを待たずに反映したいときは、リポジトリのルートで実行します。

```
npm install            # 初回のみ
npx wrangler login     # 初回のみ
npm run deploy
```

配信先の Worker 名は `wrangler.jsonc` の `name` で決まります。ここを変えると別の
URLに新しい Worker が作られてしまうため、変更しないでください。

## 主な機能

- 新規クライアント / クライアントデータ / 商談 / タスクの管理
- 企業リストの一括取り込み（貼り付け・.xlsx・.csv）と重複検出
- AI判定：Claude が web検索で各社を調べ、ランク・イベント規模・主催者・
  LINE公式アカウントを判定
  - 画面内から実行する方法（Anthropic APIキーを使用。キーは端末にのみ保存）
  - Claude に調べさせたCSVを取り込む方法（「AI調査用の指示文をコピー」から
    指示文を取得して使う）
- タスク管理：案件ごとの色分け、優先度、期間、共有タスク
  - タスクテンプレート：新規案件の登録と同時に、決まったタスク一式を起こす
  - 案件にクライアントを紐づけると、その案件のタスクは自動でそのクライアントの管理表に入る
  - クライアントごとのタスク管理表と、客先に見せる共有URL
- 配信リストのCSV書き出し、配信停止の取り込み
- バックアップ
  - 自動バックアップ：保存のたびに、その日の控えをサーバー側に残す。同じ日は
    上書きし、7日より古い控えは自動で削除される。別のパソコンからも戻せる
  - 復元ポイント：同期で内容が差し替わる直前の状態を、その端末に最大8件
  - バックアップ／復元：JSONファイルとして手元に書き出し・読み込み

## データの保存方法

データは Firestore の `workspaces/default` に、gzipで圧縮した1つの文字列として
入れている（1ドキュメント1MiBの上限に収めるため）。

読み書きはどちらも Firestore の REST API で行い、Firebase SDK は**ログイン機能
だけ**に使っている。SDKの通信部分は使わない。端末に溜まった送信待ちが何時間も
あとに届き、その時点の古い内容でサーバーを巻き戻す事故が起きたため、SDKが作った
保管領域は起動時に削除している。ここは元に戻さないこと。

### 共有URL

クライアント詳細で共有を有効にすると、`shares/<合言葉>` に客先向けの写しを置き、
`?share=<合言葉>` で開ける読み取り専用ページを出す。写しに入るのは
「クライアントにも表示する」を付けたタスクだけで、担当者や社内向けのタスクは入らない。

タスクには対応区分（弊社／クライアント）があり、共有ページでは「弊社対応」「御社対応」
として表示し、両方が混ざっている場合だけ絞り込みのタブを出す。
「見せる／見せない」（社内のみか客先公開か）と「どちらが対応するか」は別の設定。

客先に見える画面での自社の呼び方は `OUR_NAME`（現在は active channel）で決まる。
社内の画面は「弊社」のまま短く出している。

クライアントは各タスクに進捗メモを書ける。書き込み先は `shareNotes/{token}/notes` で、
1件ずつ追加する形にしてあるため、既存のメモを書き換えることはできない。
ルール側で「クライアントを名乗る」「2000文字以内」「項目は4つだけ」を強制している。
削除はクライアント自身の書き込み（by == 'client'）と、ログインした弊社側だけ。
弊社の書き込みをクライアントが消すことはできない。

上限の2000文字はアプリ側の `NOTE_MAX` とルールの両方に書いてある。片方だけ変えないこと。

ログインしない相手が読み書きするため、Firestore のルールで `shares/{token}` の read と
`shareNotes/{token}/notes` の create を開けておく必要がある。アプリ内の
「共有URLが『権限がありません』と出る場合はこちら」に、貼り付ける内容がそのまま出る。

うまく保存できないときは、画面左下の「診断」を開く。ビルド番号、保存するデータの
大きさ、直近の保存結果（エラーコードそのまま）、直近の受信内容が出る。
「通信テスト」はアプリの処理を通さず、素のRESTで読み書きを試す。
